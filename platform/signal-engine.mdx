**Apps → Signal Engine.** The live trade feed and the empirical performance metrics of every tracked quantitative strategy.

<Info>
**This API places no orders.** Nothing reachable from the signal engine can move capital. It monitors, measures, and publishes analytics; execution is handled by separate non-custodial smart contracts and Smart Executors that you activate. See [The custody model](/security/custody-model).
</Info>

## When the engine is not connected

If a deployment has no signal engine configured, this screen **reports that it is not connected**. It does not fall back to fabricated sample data or artificial charts.

This is an intentional design rule: an interface that invents metrics when its data source is offline compromises analytical integrity.

## The live feed

Signals stream over a Server-Sent Events (SSE) connection, updating dynamically without requiring a page refresh. Each signal record includes:

| Field | Definition |
| --- | --- |
| Chain and DEX | Decentralized venue and network where the asset trades |
| Pair Address | Liquidity pool contract address, verifiable on block explorers |
| Price / Liquidity / FDV | Market depth and valuation at the moment of signal detection |
| Buys / Sells / Buy Ratio | Transaction flow driving the detected movement |
| Pair Age | Time elapsed since pool creation |
| Origin | `tx` (on-chain transaction), `trade-id` (order book), or `simulated` |

The **origin** tag indicates the data source. Signals derived from authentic on-chain transactions and signals generated in simulation environments are both tracked and explicitly differentiated.

## Reading statistical indicators honestly

BlackQuant separates performance reporting into clear analytical foundations:

### Basis: what a rate actually rests on

| Basis | Definition |
| --- | --- |
| `calibration` | Complete empirical record: all resolved outcomes across historical runs and API updates |
| `stats` | Current execution session only |
| `declared` | **Self-reported claim, never an empirically verified result** |
| `none` | Early-stage strategy with no resolved outcomes yet |

<Danger>
**A declared rate is never promoted into a measurement.** If an algorithm author claims an 80% win rate, that assertion is cataloged as a claim and remains permanently tagged as such until substantiated by on-chain resolution.
</Danger>

The calibrated rate represents the primary metric: it shows what a signal has historically yielded when executed in live market conditions.

### `null` is not zero

Strategy win rates remain `null` until trades resolve. The platform never defaults unmeasured algorithms to 0%.

"Not yet measured" and "measured at zero" are fundamentally different assessments. Defaulting unmeasured algorithms to zero would falsely misrepresent new strategies as broken.

### Credible intervals

Every published metric includes a **90% credible interval**, defining the mathematical range containing the true long-term rate with 90% probability given the observed sample size:

| Displayed Metric | Resolved Samples | Empirical Meaning |
| --- | --- | --- |
| `75% [45, 93]` | ~4 | High uncertainty. The true probability could be near 50%. |
| `75% [72, 78]` | ~400 | High statistical confidence with reliable predictive power. |

Both show a 75% headline midpoint, but only the narrow interval provides dependable statistical confidence.

<Warning>
Always assess the credible interval rather than the headline percentage alone. A broad interval indicates an early sample size, regardless of how attractive the midpoint appears.
</Warning>

### Reliability bins

Strategies are segmented into confidence bins, each displaying its respective signal count, win frequency, and calibrated rate. This verifies whether a strategy exhibits higher accuracy when its confidence score rises.

A well-calibrated quantitative strategy demonstrates increasing win rates across higher confidence bins.

## Simulated performance modeling

When equity curves represent simulations, the interface details the underlying **assumptions**:

| Parameter | Impact on Results |
| --- | --- |
| Starting Capital | Scales portfolio sizing and absolute dollar gains |
| Risk Per Trade | Primary determinant of peak-to-trough drawdowns |
| Fee Basis Points | Incorporates DEX pool fees and gas costs |
| Max Leverage | Governs tail risk exposure |
| Sizing Logic | Calibrated sizing dynamically weights by measured statistical edge |

## Strategy metrics summary

| Metric | Definition |
| --- | --- |
| Total P&L % | Net strategy return accounting for transaction fees |
| Gross Win % / Gross Loss % | Separated performance components to calculate profit factor |
| Profit Factor | Gross profits divided by gross losses (`null` when zero losses are recorded) |
| Best / Worst Trade | Outlier return bounds |
| Max Drawdown % | Maximum peak-to-trough capital decline |
| Longest Loss Streak | Consecutive unprofitable executions |

## Connection timeouts

Requests to signal feeds utilize a **5-second timeout**, ensuring network interruptions produce distinct error notices rather than hanging application screens.
