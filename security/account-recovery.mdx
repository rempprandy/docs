## Forgotten password

1. Click **Forgot password?** on the sign-in screen.
2. Enter your registered email address.
3. Follow the instructions sent to your email.

<Info>
The response format is identical regardless of whether an account exists for that address. This prevents the form from being used to discover registered email addresses.
</Info>

Password reset tokens are stored as cryptographic hashes, are single-use, and expire promptly. Expired or used tokens cannot be replayed.

## Changing your password while signed in

Navigate to **Personal → Reset Credentials**.

This flow sends a verification code to your registered email address. Attempt rates are throttled to prevent brute-force attacks.

This is also the procedure to **add a password to an account created through GitHub OAuth**, which initializes without a password.

## Lost two-factor authentication device

Enter an unused **recovery code** in place of the six-digit TOTP code. Each recovery code authenticates once.

Once authenticated:
1. Navigate to **2FA / Auth Guard**.
2. Disable 2FA or re-enroll using your new device.
3. Select **Regenerate recovery codes** to provision a fresh set of ten single-use backup codes.

## Lost authenticator and no recovery codes

If you have lost access to your authenticator device and have exhausted all recovery codes, self-service recovery is not possible. Contact the [Help Desk](/platform/knowledge-and-help). Manual identity verification and proof of ownership will be required before access can be restored.

<Warning>
This highlights why storing recovery codes offline upon enrollment is essential. Having backup codes available is the difference between an immediate recovery and an extended compliance review.
</Warning>

## Irrecoverable items

<Danger>
**External wallet private keys.** BlackQuant does not hold your external private keys and cannot recover them. There is no administrative override or master key.

This is the direct foundation of non-custodial security: a platform with the capability to restore external keys would possess the capability to confiscate funds. See [The custody model](/custody-model).
</Danger>

**Funds transmitted over unsupported networks.** Cryptocurrency transfers broadcast across incompatible blockchains cannot be retrieved by validators, gateways, or platform staff.

**Transfers missing required memos or destination tags.** Contact support with the on-chain transaction hash immediately for investigation.

## Account recovery matrix

| Lost Credential | Recoverable | Recovery Method |
| --- | --- | --- |
| Password | Yes | Emailed reset link |
| 2FA device (with recovery codes) | Yes | Authenticate using single-use backup code |
| 2FA device (without recovery codes) | Via support | Identity verification and compliance review |
| Access to registered email | Via support | Identity verification and account ownership proof |
| External wallet private key | **No** | Irrecoverable by architectural design |
| Funds sent on incorrect network | **No** | Incompatible blockchain consensus |

## Preventive security habits

* [x] Recovery codes stored offline, separate from password managers
* [x] Email accounts protected with hardware keys or 2FA
* [x] Unique master password used exclusively for BlackQuant
* [x] Recovery codes regenerated when several have been redeemed
